# Habit app vs. this Task app

This is a **conceptual** distinction — there is no integration with any
external habit app. Use it to decide where something belongs.

## The deciding rule

> A **habit** must be done on a specific day — it can't be done a day
> early, and doing it early has no value. A **task** can be done anywhere
> within a window of time, possibly spanning multiple days, with no
> penalty for doing it early.

- **Habit app** — must-be-done-that-day: e.g. exercise. Doing it early
  doesn't count; there's a real notion of "today's" instance.
- **This Task app** — has a window: e.g. journaling, updating the music
  playlist. It never felt right to track these as habits because finishing
  them a few days early is perfectly fine — and that's exactly the
  characteristic that makes them tasks. They become **recurring tasks**
  here, distinct from one-off tasks but living in the same app.

Exercise is a borderline case — it roughly has to happen within the day,
so it stays a habit. Close, but not the same: the window test still
decides it.

## Why this matters

The whole task model is built on **duration** (a start/end window). A
habit has no meaningful window — it's a single day — so forcing it into a
duration model adds a fake deadline and a false "you're late" penalty.
Keeping habits out of this app keeps the duration concept honest.

## In-app affordance

Recurring tasks have a **"Move to today"** action in the editor that sets
the start date to today — useful when you want to pull a windowed
recurring task into the current day without changing its cadence.
